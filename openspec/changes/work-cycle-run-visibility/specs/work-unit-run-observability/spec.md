## IN SCOPE

- What a finished work unit leaves behind: its origin, the agent session that ran it, and the
  session's own stream.
- Where that material lives, and the guarantee that reading it needs no running process.
- The confidentiality boundary the stream crosses, and where it may therefore be written.

## OUT OF SCOPE

- Live viewing of a running unit, which is the terminal the surface already owns.
- The verdict, gate and commit record, which `work-unit-engine` already specifies.
- Any framework-side aggregation, index, or cache of run streams.

## ADDED Requirements

### Requirement: A run records where it came from

The unit record SHALL carry the origin the caller declared when starting the run, and it SHALL
be distinguishable from an origin the framework assumed. A run started with no declared origin
SHALL record that fact rather than a default that reads like a declaration.

#### Scenario: A declared origin is recorded

- **WHEN** a unit is started with a declared origin
- **THEN** the unit record carries that origin verbatim
- **AND** it is readable from the record alone, without the starting process

#### Scenario: No origin was declared

- **WHEN** a unit is started without a declared origin
- **THEN** the record states that no origin was declared
- **AND** it does not name a source that did not ask for the run

### Requirement: A run records which agent session executed it

The unit record SHALL carry the identifier of the agent session the run actually started, read
off that session rather than generated by the engine. Where the session never announced one,
the record SHALL say so.

#### Scenario: The session announced its identifier

- **WHEN** the started agent session announces its identifier on its stream
- **THEN** the unit record carries that identifier
- **AND** a reader can reach the session's own transcript from the record

#### Scenario: The session ended without announcing one

- **WHEN** the session ends without ever announcing an identifier
- **THEN** the record states that the identifier is unknown
- **AND** the run is not recorded as having no session

### Requirement: A run's stream survives the process that produced it

The system SHALL persist the started agent session's stream as it arrives, in the project's own
runtime area beside the unit record, so that a finished, killed, or timed-out run is readable
after its process and its terminal are gone. Persistence SHALL be incremental: a run killed
mid-way SHALL leave everything it had produced up to that moment.

#### Scenario: A finished run is read after the fact

- **WHEN** a unit has finished and neither its process nor its terminal exists
- **THEN** the run's stream is readable from the project's runtime area
- **AND** it is keyed to the unit whose record it belongs to

#### Scenario: A run is killed mid-way

- **WHEN** a run is killed before it produces a verdict
- **THEN** the stream persisted so far remains
- **AND** it is distinguishable from the stream of a run that completed

#### Scenario: A run that produced no stream at all

- **WHEN** a run produced no stream
- **THEN** the absence is stated
- **AND** it is not rendered as an empty but successful run

### Requirement: The stream is written where the project owns it, never into the framework

The persisted stream SHALL be written into the project's own runtime area and SHALL NOT be
copied into the framework's repository, its logs, its caches, or any diagnostic dump. Framework
diagnostics about a run SHALL name the stream's location and shape, never its content.

#### Scenario: The framework logs a run

- **WHEN** the framework logs anything about a run
- **THEN** the log carries the run's identifiers, counts, and outcome
- **AND** it carries no text taken from the session's stream

#### Scenario: A run in a project outside the framework's tree

- **WHEN** a unit runs in a project tree that is not the framework's own
- **THEN** its stream is written under that project's runtime area
- **AND** nothing derived from it is written under the framework's tree
