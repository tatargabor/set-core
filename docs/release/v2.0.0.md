# set-core v2.0.0 — the harness release

**Draft — not yet tagged.** The plan and its evidence are in [v2.0.0-plan.md](v2.0.0-plan.md).

v1.10.0 (2026-07-09) → v2.0.0: 1195 commits, 85 shipped OpenSpec changes archived, about fifteen
more shipped but not yet archived. Twenty orchestration-era changes were closed on 2026-11-23 as
superseded **without shipping their open tasks** — they are listed at the end so nobody counts
them as delivered.

**What this release is.** set-core is now the harness and fleet layer around Claude Code: one
person running many sessions across many projects. The orchestration engine it was built around
is **dormant** — still in the tree, no longer deployed or used, removed in later releases. Why:
[From orchestration to harness](../learn/from-orchestration-to-harness.md).

## Breaking changes

- **The `/set:*` orchestration and git-messaging slash commands are no longer deployed.**
  `/set:sentinel`, `/set:decompose`, `/set:plan-review`, `/set:start`, `/set:write-spec`,
  `/set:new`, `/set:work`, `/set:list`, `/set:merge`, `/set:close`, `/set:loop`, `/set:push`,
  `/set:status`, `/set:audit`, `/set:forensics`, `/set:harvest`, `/set:help`, `/set:msg`,
  `/set:inbox`, `/set:broadcast`. The next `set-project init` removes the copies it deployed
  earlier — only those not edited locally. Measured before removal: zero calls in 30 days.
- **The memory subsystem is removed** (`set-memory`, `set-memoryd`, the memory hooks, 27 memory
  MCP tools, `/set:memory`, `/set:todo`). Claude Code's own per-project memory replaces it.
  Measured reason: 168 of the 187 lines it injected in 21 days were false "user frustrated"
  records.
- **Removed integrations:** the integration-knowledge-pack (IKP) bridge introduced in v1.10.0,
  the legacy Figma pipeline, the external design-tool service, and a dead API module.

## The fleet

The dashboard became a fleet view of every agent session on the machine, with an agent owner
that holds their terminals.

- Start, restore and stop agents across projects; restore the last composition; start an agent
  in a worktree; docking per project; agent order and stage tree; idle sessions closed by a timer.
- Terminals in the browser: links and typed file views, image paste, media opened on the desktop,
  a tmux viewer; files and pages opened in the desktop's own apps (Linux and macOS).
- Recorded sessions: list, peek, restore across projects.
- Account usage bars (Claude pool, GLM), handover markers, structured notices, input attention.
- **Question relay and wait detection:** a session's question or permission prompt reaches the
  dashboard and a phone; **auto-answer** proposes a reply from the session's own sources and
  sends it after a window — never an outward step, never a permission.
- A watchdog probing the fleet for quiet failures; macOS fleet discovery and agent owner.

## Projects, deploy and the machine

- **`set-doctor`** — the machine check, every finding with the command that fixes it.
- **Project role rules** — `set-project roles` writes a git-excluded rule per project with its
  role and relations; `set-project archive` marks a project "do not develop".
- Registration no longer deploys implicitly; relay hooks are wired on register; registry archive
  and prune by name.
- Deploy provenance: a deploy never overwrites a file the project edited; scaffold is seeded once,
  framework rules keep flowing.

## Safety

- **`set-leakscan`** at commit (staged lines and the message), push and agent-tool level, with a
  private deny-list, file-name classes and an environment-identity check; masked output.
- The shared-checkout guard: a commit cannot sweep another session's staged work.
- A guard on dependency installs inside worktrees, which could rewrite the host repository's git
  hooks.

## Project status, boards and releases

- The **consumer status contract** — a versioned command a project exposes; set-core reads bugs,
  changes, releases, the test system and the live system through it, domain-free.
- Declared field roles, stage order and log follow; a generic board view; status-screen density
  and filters.
- **Wave board** — a progress board a project publishes for the people it works with: kanban
  view, staleness, assignees, answers on the page, waits, batched and on-request publishing, a
  release selector, shared and linked boards.

## Models and providers

- Explicit provider selection per agent (direct and gateway-backed), never a silent fallback.
- Model mapping as configuration data, one unified model config, model ids following upstream
  releases, an upstream model watch; GLM usage monitoring.

## Knowledge

- `set-kb` — knowledge-base search over a project's documents, CLI and MCP, with Hungarian
  stemming and linked projects.

## Upgrading

```bash
git pull && ./install.sh
set-doctor
set-project init --dry-run    # in each project: lists what is removed, and what is kept because you edited it
set-project init
```

Restart `set-web` and, when none of its agents is working, `set-agent-owner`, so the running
services drop the removed code.
